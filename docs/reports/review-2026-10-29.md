## 已复现并修复的问题

### 1. HTTP 服务自己承担鉴权边界

此前只有 Scala CLI 拒绝无令牌的非回环监听，公开的 Java `EngineHttpServer.start` 可以直接绕过它。
现在先解析一次地址，再检查将要绑定的同一地址：无令牌时只允许已解析的回环地址。
带令牌的通配地址仍可启动，`/jobs` 仍执行令牌校验；`/health` 的已有契约不变。
文件作业的数据根仍由组合根 CLI 负责，HTTP 模块没有新增对文件作业的依赖。

回归先确认旧实现没有拒绝直接绑定；新增两项测试同时覆盖拒绝与合法带令牌场景。

### 2. 事务失败不能隐式提交，也不能丢掉原始错误

此前事务没有捕获 `Error`，退出时恢复自动提交会把已写入的部分数据提交。
新增测试以 `AssertionError` 确定性复现该行为；另一测试关闭连接后再抛出原始错误，复现清理异常掩盖原错。
修复后 SQL、运行时异常和 `Error` 均尝试回滚。只有提交或回滚已成功才恢复自动提交；
若无法回滚或恢复状态则关闭连接，后续操作明确失败，不能继续使用结果不明的连接。
回滚、关闭错误保留为原始异常的 suppressed 信息，正常回滚后下一笔事务仍可提交。

依据：[JDBC 自动提交契约](https://docs.oracle.com/en/java/javase/25/docs/api/java.sql/java/sql/Connection.html#setAutoCommit(boolean))。
关闭自动提交期间切回自动提交会提交当前事务，因此恢复状态不是无害的清理动作。

### 3. 用户选择的先后顺序优先于后台完成顺序

`ProfileService` 在发起选择时记录代次；“保存并使用”在保存前就取得该代次。
较早的保存、解密或删除完成时，不能替换用户后来选择的连接。
服务只对短暂的状态应用加锁，不在锁内等待存储或网络操作。

设置表单分别检查打开代次和口令输入修订。切换表单后的旧保存/删除只刷新列表，
旧错误不落到新表单；迟到的已存口令不覆盖用户刚输入的值。忙碌状态记录未完成操作数，
避免一个操作完成后提前允许另一个操作的重复提交。

作业视图的预设、错误和最近运行按选择代次接收，不能只比较作业名字。
即使两个连接都有 `echo`，前一个连接的缓存结果也不会显示在后一个连接下。

这些回归使用可控存储/界面队列与完成信号，不以不稳定的计时断言制造“偶发成功”。

### 4. 原生复核发现参数值被无障碍名称覆盖

真实 Windows 包中，参数框已显示中文输入，但 UIA 返回的值仍为 `message`；选项框同样把 `append`
读成 `mode`。两项回归复现了这个差异。共享参数组件现在使用 `Label.labelFor` 关联字段名，
保留控件实际的文本、当前选择和默认值；作业及流水线表单都受益。界面与端到端测试也通过标签关联定位字段。
依据：[JavaFX accessibleText 的覆盖语义](https://openjfx.io/javadoc/25/javafx.graphics/javafx/scene/Node.html#accessibleTextProperty())
与 [Label.labelFor](https://openjfx.io/javadoc/25/javafx.controls/javafx/scene/control/Label.html#labelForProperty())。
