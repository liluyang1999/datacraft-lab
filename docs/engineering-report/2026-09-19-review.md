# 2026-09-19 数据处理与 Airflow 复盘

本轮覆盖配置、文件 IO、执行引擎、Spark 计算、CLI/HTTP、Airflow DAG、容器与部署定义，
保留现有模块边界。使用方法见 [数据处理契约](../data-processing.md)、
[Airflow 指南](../../orchestration/airflow/README.md) 和
[部署指南](../deployment/cloud-and-deployment.md)。根目录旧复盘报告作为历史记录保留。

## 修复与取舍

| 范围 | 原有问题 | 本轮处理 |
| --- | --- | --- |
| 小文件 CSV | 带引号的空记录在 EOF 丢失，BOM 与错误引号被误读 | 保存逻辑记录状态，去除首部 BOM，严格校验引号和分隔符 |
| Spark CSV | 推断类型可能丢失编号格式或数值精度，计数可能跳过坏字段 | 提供显式 DDL schema、文本读取选项与统一 CSV 规则；CSV 计数完整解析记录 |
| 转换写入 | 重复扫描输入，坏输入覆盖旧输出，输入输出重叠 | 缓存并完整验证输入后写入，复用缓存计数，拒绝路径重叠，最终释放缓存 |
| 写入模式 | ignore/append 的行数语义不清，转换后无一致性门槛 | 报告本批次行数和 skipped；row-count 的 expectedRows 不符即失败 |
| Spark/引擎 | 托管任务可能停止外部 Session，Scala checked exception 逃逸 | 串行管理 Session 所有权，拒绝外部活动 Session；统一失败结果并保留中断语义 |
| Airflow | 模板参数进入 shell，退出码 99 可被跳过，Spark 日志覆盖结果 | 参数通过环境变量逐项引用；非零退出失败；独立临时结果文件传 JSON 到 XCom |
| DAG 数据流 | SFTP 依赖缺失可能被降级，缺少目录/行数/重跑保障 | 必需 provider、创建下载父目录、下游核验行数、单个活动 DAG run、超时和有界重试 |
| HTTP/CLI | 非法生命周期和短路径断连，重复解码，master 优先级错误 | 明确 400/404/405，路径只解码一次；严格参数校验和结构化输出 |
| 本地 IO/SFTP | 哈希整文件入内存，符号链接越界，超时取值和连接清理缺口 | 流式哈希、链接拒绝、超时范围校验、known-hosts、失败连接释放及密码脱敏 |
| 部署 | 初始化错误被隐藏，缺少执行 API/JWT 配置，卷路径与健康检查不匹配 | 失败即停止、幂等管理员创建、共享 JWT、Postgres 18 卷布局、可运行健康检查 |
| Swarm | 本地卷下任意分散 worker 会读到不同数据 | 指定数据节点；改为真正多节点前必须配置共享存储 |

缓存降低重复读取，但占用内存/磁盘；多行 CSV 默认开启会限制单文件切分。
显式 schema 才能定义编号和十进制精度。overwrite 先验证输入不等于事务化写入：
写入阶段断电、网络或磁盘失败仍需恢复；append 重试仍可能重复。上述边界已写入使用契约。

## 验收证据

本地完整验收使用 WSL Ubuntu、Temurin 25.0.4.1+1、Python 3.12.3、Airflow 3.3.1、
Spark/PySpark 4.2.0。Airflow providers 采用对应 Python 3.12 官方 constraints，`pip check` 通过。

| 门槛 | 结果及覆盖 |
| --- | --- |
| Maven `spotless:apply verify` | 8 个 reactor 项目通过；Spotless、Checkstyle、Enforcer、编译、测试、shaded JAR 打包 |
| JVM 测试 | 73 项：Java 48、Scala 25；失败、错误、跳过、取消均为 0 |
| 真实 Spark | 17 项 Spark 模块测试含 7 项运行时集成测试：精度、多行、坏数据保留旧输出、路径重叠、写模式、计数、Session 所有权 |
| HTTP | 实际临时端口和 HTTP 客户端验证成功、非法输入、缺失作业、方法、路径解码及缺少作业名 |
| Airflow 合约 | 6 项真实 provider/DagBag/模板/进程边界测试，含特殊字符、退出码 99 和结构化结果清理 |
| 初始化 | 4 项脚本回归，验证迁移/用户查询/创建错误、重复初始化、以连字符开头的密码及字面参数 |
| 完整 DAG | `datacraft_engine_jobs` 一次、`datacraft_spark_etl` 两次、`datacraft_sftp_ingest` 一次，均成功 |
| 数据核验 | 含空格和单引号的输入路径、中文、多行 CSV；转换和下游均为 2 行；SFTP 下载逐字节一致 |
| 实际初始化 | 同一临时 metadata/FAB 数据库初始化两次，第二次保留已有管理员；生成的密码以 `-` 开头 |
| 部署静态门槛 | Bash 语法、ShellCheck、Docker Compose 2.40.3 `config`、Docker 29.1.3 `stack config` 通过 |

已观察回归失败后再修复 CSV、Spark、HTTP 等行为，并使用最终全量门槛复验。
测试中可见依赖弃用、Hadoop 原生库回退、shaded JAR 重叠元数据等提示；没有将取消或未执行的测试计入通过数。
真实 SFTP 端到端使用 Airflow provider 和临时本地服务器；Java SFTP helper 的主机信任、
网络超时和第三方服务器组合仍应按目标环境验收，不能由配置单元测试替代。

最终本地验收 JAR 大小为 9,257,105 字节，SHA-256 为
`35918e701744839d57aa962018c543f3688381c627ce07f0b294cd186c00210b`。
该指纹标识本次本地构建，不代表已发布制品；CI 独立重新构建。

## 可重复验证

```bash
./mvnw -B -ntp verify
python -B -m unittest discover -s deploy/tests -v
python -B -m unittest discover -s orchestration/airflow/tests -v
python -B orchestration/airflow/tests/runtime_smoke.py --jar datacraft-cli/target/datacraft-cli.jar
bash deploy/tests/container_smoke.sh
```

前四项需要 JDK 25.0.3+ 与指南中的 Python 环境；最后一项还需要 Docker daemon，
会构建 JVM/Airflow 镜像，验证容器 HTTP/CLI、依赖一致性和镜像内完整 DAG。
[CI 工作流](../../.github/workflows/ci.yml) 独立执行构建、DAG、脚本、拓扑和容器五个任务，
应按提交对应的 [Actions 记录](https://github.com/liluyang1999/datacraft-lab/actions/workflows/ci.yml)
检查实际 runner 和步骤结果。本机没有 Docker daemon，容器运行门槛交由 CI 执行。

## 清理与适用边界

运行时测试在临时目录中保存 metadata、账号、下载数据、Parquet 和日志并自动删除，
SFTP 服务在 finally 中关闭。任务结束前删除各模块 target、隔离工具环境、临时配置和测试日志，
复核工作区及进程；保留本记录和可重复测试代码，不提交原始错误日志或测试凭据。

Windows 本机 JDK 25.0.2 的 NIO Selector 初始化失败，完整验收在 Linux/WSL 执行；
不能把 Windows 上取消的 Spark 测试视为通过。此次没有操作线上数据库、真实 SFTP 账号或生产集群。
Postgres 旧卷迁移、生产凭据、真实 Celery 多节点、共享存储和外部认证网关须按部署环境单独验收。

[Spark 4.2 CSV](https://spark.apache.org/docs/4.2.0/sql-data-sources-csv.html)、
