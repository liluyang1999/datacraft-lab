Maven 构建配置报告

面向生产级多模块 JVM 工程的 Maven 父 POM、子模块 POM、生命周期、插件矩阵和 profile 说明。

一、Maven 工程定位

本项目使用 Maven Wrapper 固定 Maven 入口，通过父 POM 管理多模块 reactor。父 POM 是唯一的构建治理中心：统一模块列表、依赖版本、插件版本、质量门、发布产物 profile 和审计 profile。 子模块 POM 只声明模块坐标、依赖关系和少量模块特有插件，避免配置散落。

这种布局符合 Maven 的约定优先原则：默认生命周期仍由 Maven 管理，项目只显式声明必须固定的版本、 编译目标、质量规则和与 Java/Scala/Spark 混合工程相关的差异。

Maven Wrapper

.mvn/wrapper/maven-wrapper.properties 使用 Apache Maven Wrapper 3.3.4 的 distributionType=only-script：仓库只提交 mvnw、mvnw.cmd 两个脚本和该属性文件， 不提交 maven-wrapper.jar。脚本下载 Maven 3.9.16 的 bin.zip，并用 distributionSha256Sum 校验其 SHA-256，不符时以 Failed to validate Maven distribution SHA-256 退出。

校验只在下载时进行，即 MAVEN_USER_HOME（默认 ~/.m2）下的 wrapper/dists 中还没有对应发行版时；已存在的目录直接复用。Linux、macOS 和 WSL 需要 unzip：没有它时脚本改为下载 .tar.gz，其 SHA-256 与固定的 zip 校验值不符， 会以上述校验失败退出。mvnw.cmd 在 powershell.exe 中执行下载与校验。 CI 在 Verify 之前检查校验值已固定、仓库中没有 maven-wrapper.jar， 并确认把校验值改错的副本拒绝运行。

二、父 POM 布局

区域 作用 生产规范意义
groupId/artifactId/version 定义父项目坐标：com.example.datacraft:datacraft-lab:0.1.0-SNAPSHOT。 所有子模块继承同一版本，保持 reactor 内部依赖一致。
packaging=pom 声明当前项目是聚合父项目，不直接产出业务 jar。 清晰区分父级构建治理和子模块产物。
scm 记录 Git 远端地址和源码管理元数据。 为发布、构建追踪和未来 CI/CD 元数据补齐基础。
modules 声明 reactor 模块顺序和成员：common、config、io、engine、jobs、spark、api、cli， 连同父项目共 9 个 reactor 项目。 由 Maven 自动计算模块构建顺序，避免手写脚本排序。
properties 集中定义 Java、Scala、Spark、依赖和插件版本。 版本单点治理，避免子模块重复硬编码。
dependencyManagement 统一锁定依赖版本，但不强制引入依赖。 子模块只声明需要什么依赖，版本由父 POM 管理。
pluginManagement 统一锁定生命周期插件和扩展插件版本。 避免依赖 Maven 默认插件版本，提升构建可重复性。
build.plugins 声明所有模块默认执行的质量门和生命周期增强。 让 mvn verify 成为统一可信验证入口。
profiles 提供发布产物和依赖审计等显式启用能力。 默认构建保持快速稳定，生产发布和审计按需开启。

三、属性与版本矩阵

父 POM 的 properties 是项目唯一版本矩阵。核心分组如下：

分组 属性示例 说明
编码与可重复构建 project.build.sourceEncoding, project.build.outputTimestamp 固定 UTF-8 和归档时间戳，减少跨机器构建差异。
JDK 编译目标 java.version, maven.compiler.release java.version 为 25，maven.compiler.release 取 ${java.version}， javac 的 release 与 scalac 的 -release: 都引用它。以 Java 25（当前 LTS）字节码为目标； Spark 4.2.0 支持 Java 17/21/25，并弃用 25.0.3 之前的 Java 25 版本，建议使用 25.0.3 及以上版本。
Scala/Spark 生态 scala.version, scala.binary.version, spark.version, spark.scope Scala 二进制版本影响 Spark 依赖坐标，必须集中维护；spark.scope 默认为 provided，Spark 运行时由集群 / spark-submit 提供，使 CLI 制品保持精简。
JSON 序列化 jackson.version（以 jackson-bom 方式 import） 通过 BOM 统一锁定 Jackson 全家桶版本（当前 2.22.3），供 datacraft-api 的 EngineJson 编码 HTTP 响应和 CLI 的 JSON 结果。在 spark-submit 下，Spark 默认 （spark.driver.userClassPathFirst=false）先加载自带的 Jackson（Spark 4.2.0 为 2.21.2），替代制品内的版本； CI 的 Airflow 作业用 PySpark 4.2.0 的 spark-submit 运行打包后的 CLI，覆盖这一组合。
测试依赖 junit.jupiter.version, scalatest.version, sshd.version Java 和 Scala 测试框架版本统一锁定；sshd.version 固定 SFTP 测试使用的嵌入式 Apache MINA SSHD 服务器。
测试 JVM 与测试门 test.nio.jvm.args, spark.test.jvm.args, surefire.failIfNoTests test.nio.jvm.args 为 -Djdk.net.unixdomain.tmpdir=${project.build.directory}： Windows 上的 NIO Selector 在该目录创建 AF_UNIX 唤醒套接字，而部分 Windows 用户 TEMP 目录无法承载 AF_UNIX 套接字；模块构建目录在各操作系统上都可用。spark.test.jvm.args 是 Spark 嵌入测试 JVM 所需的 --add-opens 等参数，spark-submit 运行时会自动注入等价设置。 surefire.failIfNoTests 默认 true。
插件版本 maven.compiler.plugin.version, maven.surefire.plugin.version, checkstyle.version 所有 Maven 插件版本显式锁定，配合 Enforcer 禁止默认漂移；surefire 与 failsafe 为 3.5.6。 checkstyle.version 固定 Checkstyle 引擎为 14.1.0，不使用 maven-checkstyle-plugin 3.6.0 默认的 9.3，后者无法解析 record pattern、带 when 的 switch 标签和灵活构造器体。

四、插件职责矩阵

插件 绑定/用途 本项目配置重点
maven-clean-plugin 清理 target。 显式版本，避免 Maven 默认生命周期版本漂移。
maven-resources-plugin 处理 main/test resources。 统一 UTF-8 编码。
maven-compiler-plugin Java 编译。 使用 release=25（${maven.compiler.release}）、保留方法参数名、显示编译警告。
scala-maven-plugin Scala main/test 编译。 绑定 compile/testCompile，传入 -release:${maven.compiler.release}，并开启 deprecation、feature、 unchecked、Xlint。
maven-surefire-plugin test 阶段单元测试。 排除 *IT/*ITCase，避免单元测试和集成测试混跑；argLine 为 ${test.nio.jvm.args}；failIfNoTests 取 ${surefire.failIfNoTests}， JUnit 扫描不到任何测试的模块以 No tests were executed! 失败。datacraft-cli 与 datacraft-spark 由 ScalaTest 运行测试，把该属性设为 false。
maven-failsafe-plugin integration-test 与 verify 阶段集成测试。 包含 *IT/*ITCase，确保资源清理阶段可执行；目前没有模块包含此类测试。
scalatest-maven-plugin 运行 ScalaTest 套件。 argLine 为 ${test.nio.jvm.args}（datacraft-spark 另加 ${spark.test.jvm.args}）；把 JUnit XML 写入 surefire-reports，方便 CI 聚合测试结果。
maven-jar-plugin 标准 jar 产物。 写入 Implementation/Specification manifest 元数据。
maven-shade-plugin CLI 可执行 fat jar。 只在 datacraft-cli 模块执行，设置 mainClass、合并 service 文件和 reference.conf。 manifest 写入 Multi-Release: true，使依赖的 META-INF/versions 类（jsch 的 Ed25519/X25519/ML-KEM、Jackson）在 fat jar 中生效；排除签名文件以及依赖的 module-info.class 和 META-INF/versions/*/module-info.class。
spotless-maven-plugin 格式检查。 Java 使用 google-java-format，Scala 使用 scalafmt；XML、YAML、properties、Markdown、docs 下的 HTML/CSS 与 Airflow Python 统一 LF 行尾、去除行尾空白并以换行结尾。
maven-checkstyle-plugin Java 静态规则。 集中读取 config/checkstyle/checkstyle.xml，在 verify 阶段检查 main 与 test 源码； 通过插件依赖把 Checkstyle 引擎固定为 ${checkstyle.version}（14.1.0）。
maven-enforcer-plugin 构建环境与 POM 规则。 enforce-build-environment：JDK [25,)、Maven [3.9.0,)、插件必须显式声明版本、 禁止在同一 POM 中重复声明依赖、禁止项目级仓库，并禁止低于 2.22.3 的 jackson-core 与 jackson-databind 进入依赖图 （GHSA-wv8q-qhhj-9h54 等 4 个公告）。warn-deprecated-jdk：JDK 低于 25.0.3 时以 WARN 级别提示升级，构建继续。datacraft-engine 另有 enforce-module-boundaries，见第六节。
maven-source-plugin 源码 jar。 在 release-artifacts profile 中启用。
maven-javadoc-plugin Javadoc jar。 在 release-artifacts profile 中启用，doclint 排除 missing。
maven-dependency-plugin 依赖分析。 在 dependency-audit profile 中启用。
maven-install-plugin, maven-deploy-plugin, maven-site-plugin 安装、部署、站点生命周期。 显式锁定版本，满足生产构建的插件版本完整性。

五、生命周期与命令

命令 用途 推荐场景
.\mvnw.cmd test 编译并运行单元测试。 本地快速验证。
.\mvnw.cmd verify 执行测试、集成测试 verify、格式检查、Checkstyle、Enforcer、打包校验。 提交前的默认入口。
./mvnw -B -ntp verify 与上一行相同的完整门禁，非交互输出。 Linux、macOS、WSL 与 CI（ubuntu-24.04）。
make verify 调用 $(MVN) -B -ntp verify，MVN 默认 ./mvnw。 需要系统 Maven 时用 make MVN=mvn verify。
.\mvnw.cmd -pl datacraft-cli -am package 构建 CLI 及其依赖模块。 本地运行 CLI 或 Airflow 调用前。
.\mvnw.cmd -Prelease-artifacts verify 额外生成 source jar 和 javadoc jar。 发布、归档或制品库上传前。
.\mvnw.cmd -Pdependency-audit verify 运行依赖分析。 版本升级、发布前审计。
.\mvnw.cmd spotless:apply 自动修复格式。 提交前整理格式。

在多个模块上用 -Dtest=... 只跑部分测试时，为了让没有匹配测试的模块不失败，需要同时传入 -Dsurefire.failIfNoSpecifiedTests=false -Dsurefire.failIfNoTests=false；surefire 报错信息建议的 -DfailIfNoTests=false 在本项目中不起作用，因为插件配置读取的是 surefire.failIfNoTests 属性。

六、子模块 POM 规则

子模块 POM 遵循最小配置原则：

  • 必须继承父 POM。
  • 必须只声明自身 artifactId 和 name。
  • 依赖版本优先来自父 POM dependencyManagement。
  • 插件版本不得在子模块硬编码。
  • 只有模块特有行为才在子模块声明插件，例如 CLI 的 shade 打包。
  • 模块级开关通过覆盖父 POM 属性表达，例如 datacraft-cli 与 datacraft-spark 的 surefire.failIfNoTests=false。

datacraft-engine 的 enforce-module-boundaries 执行用 bannedDependencies 排除全部 com.example.datacraft 构件和 org.apache.spark，只放行 datacraft-common； 违反时 validate 阶段失败并提示 engine 只能依赖 common、不得依赖 Spark。

这种规则使模块结构可扩展，也避免每新增一个模块就复制一份构建配置。

七、Profile 设计

release-artifacts

用于发布前生成源码包和 Javadoc 包。默认构建不强制生成这些制品，避免本地迭代时不必要的时间成本。

dependency-audit

用于运行 Maven Dependency Plugin 的依赖分析。当前设置为不因 warning 阻断构建，适合先作为审计报告入口。 等项目依赖边界进一步稳定后，可逐步收紧为失败即阻断。

bundled-spark

将 spark.scope 由 provided 切换为 compile，把 Spark 运行时一并打入制品， 用于没有 spark-submit 的环境下直接 java -jar 运行。产物体积显著增大， 仅建议笔记本规模的本地实验使用。它使用同一份 shade 配置，因此同样是 Multi-Release jar。

八、官方依据

  • Maven Compiler Plugin 官方建议显式设置 release，避免默认 source/target 漂移： maven-compiler-plugin
  • Surefire 用于 test 阶段执行单元测试： maven-surefire-plugin
  • Failsafe 用于集成测试，并应通过 mvn verify 验证结果： maven-failsafe-plugin
  • Source Plugin 用于生成源码 jar： maven-source-plugin
  • Javadoc Plugin 用于生成 Javadoc 和 Javadoc jar： maven-javadoc-plugin
  • Enforcer Plugin 用于约束 Maven/JDK 环境和构建规则： maven-enforcer-plugin
  • Maven Wrapper 的 only-script 分发类型与 distributionSha256Sum 校验： Maven Wrapper
