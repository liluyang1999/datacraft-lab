# 数艺工坊 · 项目章程

数艺工坊是 datacraft-lab 的桌面控制台：在一台开发机或运维机上，看清后台计算是否健康、正在运行什么，
并带参数启动作业与流水线、查看结果和失败原因。它是控制和观察的中枢，自身不保存任何业务数据。

## 用户与主要任务

使用者是这套平台的运维者本人：熟悉作业与 DAG 的名字，关心“现在是否正常”和“刚才那次运行怎样了”。

1. 打开即知：引擎 API 与 Airflow 是否可达、延迟多少、调度器与元数据库是否健康。
2. 运行作业：选作业、填参数（带已知参数的提示与常用预设）、启动、看结果与指标。
3. 驱动流水线：浏览 DAG、暂停或恢复、带配置触发一次运行、跟踪任务状态与日志。
4. 回看：最近的运行、连接状态的变化、出过的错。

## 对接的后台

| 后台 | 地址（Compose 默认） | 认证 | 用途 |
| --- | --- | --- | --- |
| 引擎 API（`datacraft-api`） | `http://127.0.0.1:8088` | Bearer 令牌（`DATACRAFT_API_TOKEN`） | 健康、作业目录、同步运行作业 |
| Airflow 3.3.2 REST API v2 | `http://127.0.0.1:8080` | `POST /auth/token` 换取 JWT（FAB 用户名与口令） | 健康、DAG、运行、任务实例、日志、触发 |

两者都只绑定回环地址；远程主机经 SSH 隧道转发端口后同样使用。Swarm 部署不发布引擎 API，
需要隧道到覆盖网络内的服务（见部署教程第 6 节）。

## 约束

- **技术栈：**JavaFX 25.0.5 与 JDK 25（字节码 25），与后端相同的 Maven 3.10.0 Wrapper、零警告、
  格式化与静态检查规则；不引入 JavaFX 之外的 UI 框架。
- **位置：**应用（源码、资源与构建）在仓库根目录的 `desktop/` 内，是独立的 Maven 工程：沿用根 POM 的
  构建约定（Java 下限、Enforcer、格式与静态检查），但不在后端的反应堆里，后端构建与发布不受它影响。
  它也遵守仓库的目录约定：测试在 `tests/jvm/datacraft-desktop/`，文档在 `docs/desktop/`。
- **本机数据：**只在用户主目录的 `.datacraft/` 下保存配置与临时缓存，使用 SQLite（`sqlite-jdbc`）。
  不保存业务数据，也没有服务端数据库。
- **安全：**令牌与口令不写入明文：Windows 用 DPAPI 绑定当前用户加密，其他系统用仅当前用户可读的
  密钥文件加密；可以选择不保存，只在本次运行中使用。日志与界面从不显示秘密。
- **体验：**界面线程只做界面；任何网络与磁盘操作都在后台完成，操作在 100 ms 内有反馈，
  滚动与切换不掉帧。
- **界面：**简洁雅观、清新易懂：以图形与动态的变化为主要交互，状态用形状与颜色表示，文字只留名字与数字，
  解释放进悬停提示，不在界面上放复杂的长文本（2026-10-28 起，见界面设计第二版）。

## 非目标

- 不替代 Airflow 的 Web 界面：不编辑 DAG，不管理用户、连接、变量与池。
- 不在本机运行作业或 Spark；所有计算都在后台进行。
- 不做多用户、团队共享或云同步；不做移动端。
- 不新增后端接口：只使用现有的引擎 API 与 Airflow REST API。

## 成功标准

见 [循环计划](loop/plan.md) 各轮的验收条件；总体上：

- 冷启动到可交互不超过 1.5 s（本机），启动与运行过程中控制台 0 条警告；
- 后台不可达时界面仍然流畅，明确说明原因与下一步，并在后台恢复后自动恢复；
- 对真实的引擎 API 与本机 Compose 部署的 Airflow 完成作业运行、DAG 触发与日志查看的端到端验证。
