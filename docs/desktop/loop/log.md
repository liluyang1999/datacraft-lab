# 循环记录

每轮结束时追加一节：目标、做了什么、证据、遗留。

## 规划（2026-10-27）

- **目标：**在写代码之前定下章程、架构、界面设计、接口对接、流畅度与测试方案，以及各轮计划。
- **做了什么：**核对了引擎 API 的状态码契约（`design/data-contracts.md`）与 Airflow 3.3.2 镜像内的
  OpenAPI 定义；确认 JavaFX 25.0.5（2026-10-20 发布）、sqlite-jdbc 3.53.4.0 为当前版本；JavaFX 25 需要
  JDK 23 以上，在 JDK 24 以上需要 `--enable-native-access=javafx.graphics`，否则启动时有警告；
  sqlite-jdbc 的本机库加载同样需要授权（`ALL-UNNAMED`）。JavaFX 25 没有内置的无界面平台，CI 上的界面
  测试用 Xvfb。
- **证据：**本目录下的六份文档。
- **遗留：**无；下一轮是 L0。

## L0–L5 实现与验证（2026-10-27）

- **目标：**按[计划](plan.md)完成 L0 至 L5，逐条核对验收条件。
- **做了什么：**
  - 分层实现（`api`、`store`、`service`、`viewmodel`、`ui`），蓝晒主题的浅色与深色两套，五个视图、侧滑面板、通知、
    键盘操作与减少动效。
  - 打包脚本 `cicd/desktop/package_desktop.py`（jlink、jpackage、AOT 缓存），CI 的 `desktop` 作业（Xvfb）。
  - 端到端测试（`-Pe2e`）。
- **证据：**
  - `./mvnw -f desktop/pom.xml -B -ntp verify`：76 个测试全部通过，0 条警告，连续三次相同；
    `tests/ci/test_package_desktop.py` 12 个测试通过。
  - 界面测试把每个视图的浅色与深色、触发面板、日志查看器存为 `desktop/target/ui-snapshots/*.png`，逐张检查过。
  - 端到端，对 CLI jar 启动的 `serve-api`（回环地址、随机令牌）：作业目录、`echo` 中文往返、`csv-profile`
    指标、缺参数的失败结果、未知作业、错误令牌，以及窗口里运行作业，全部通过。
  - 端到端，对本机 Compose 部署（Airflow 3.3.2 与 `datacraft-api`）：登录、健康、版本、三个 DAG、暂停与恢复、
    触发 `datacraft_engine_jobs`（约 9 s 到 success，`noop` 与 `echo` 成功，日志可读），窗口两个后台都为正常；
    `csv-profile` 需要与引擎共享的目录，这里跳过，已对 `serve-api` 验证。
  - 启动：改进前首帧约 2.55 s；本机数据与工具包并行启动、窗口图标推迟后约 1.7 s；打包的应用目录带 AOT 缓存
    约 1.1–1.3 s，保留时间戳复制到别处后仍为约 1.1–1.2 s。按 README 的 `javafx:run` 能启动，约 2.2 s。
  - 流畅度：预热后切换视图无超过 50 ms 的停顿；切换主题在 100 ms 以内（单个视图实测 12–75 ms）；
    1500 行日志滚动无超过 50 ms 的停顿；重启后窗口位置、大小、主题与上次的视图都恢复。
- **发现并修复的缺陷**（除特别说明外，都先有失败的测试）：
  - 这台机器的系统 TEMP 放不下 JDK 的 AF_UNIX 管道套接字，HTTP 客户端无法创建、应用启动即退出：
    启动器把 `jdk.net.unixdomain.tmpdir` 指到 `~/.datacraft/tmp`。
  - `Map.copyOf` 不接受 `null`：运行配置里有 JSON `null` 的 DAG 运行会让整个运行列表失败；指标也因此失去顺序。
  - Airflow 的 409 把 SQL 语句放在 `detail` 里：现在只显示原因。
  - 每解析一个 DAG 运行就新建一个 JSON 映射器：改为共用一个。
  - 代码审阅发现的 13 处：关闭窗口时 HTTP 客户端等待进行中的作业运行，进程不退出；作业等待超时被当成“无法连接”；
    切换连接后旧连接的检查能为新连接“担保”令牌正确；切换连接后旧的作业列表、选择与结果仍在；“使用此连接”
    忽略未保存的修改；慢的测试结果显示在别的连接下；回到设置时清空正在新建的连接；日志加载中再打开另一份日志
    时不再加载；先前所选运行的任务显示在新选的运行下；暂停前已发出的轮询把开关拨回；预设列表显示到别的作业下、
    失败无提示；映射任务的日志缺少 `map_index`；日志面板的监听器泄漏（这一处直接修复，没有测试）。
  - 主题切换要重排全部节点：改为根节点切换样式类、并在切换前取下隐藏的视图；视图改为常驻场景只切换可见性，
    避免每次重新匹配 CSS。
  - 测试本身：桩服务器改为每个请求一个线程，与真实服务器一致；依赖时序的测试改用确定的同步点。
- **遗留：**
  - CI 的 `desktop` 作业要在推送后看第一次运行（Linux 上的 Xvfb、Temurin 是否带 jmods）。
  - Linux 运行器可能没有中文字体，CI 的截图里中文可能显示为方框，不影响测试。
  - AOT 缓存按时间戳核对 jar：复制应用目录要保留时间戳；目前只生成应用目录，没有安装包。
  - 流水线视图的主题切换最慢约 75 ms，在 100 ms 预算内但余量不大。
