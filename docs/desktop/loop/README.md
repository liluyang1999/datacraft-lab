# 循环工程

数艺工坊按一轮一轮的闭环开发。每一轮都是同一个循环：

```
   ┌─────────► 1. 目标 ─────────┐
   │      本轮要交付什么、怎样算完成  │
   │                              ▼
5. 记录                       2. 设计
写入 log.md：做了什么、        先改文档（架构、界面、接口）
证据、遗留与下一轮               再动代码
   ▲                              │
   │                              ▼
4. 验证  ◄──────────────── 3. 实现
跑全部检查，对照验收条件       小步提交，每个缺陷先有
逐条给出证据                     失败的测试
```

## 规则

1. **一轮一个目标。**目标与验收条件写在 [plan.md](plan.md)，开始前确认，结束时逐条核对。
2. **先文档后代码。**设计有变化时，先改 [架构](../architecture.md)、[界面设计](../ui-design.md) 或
   [接口对接](../api-integration.md)，代码随后跟上；文档与代码不一致视为缺陷。
3. **证据而不是感觉。**“完成”需要当轮的新证据：构建与测试的退出码、截图或测量值、端到端操作的结果。
   上一轮的结果不能代替这一轮。
4. **失败先有测试。**每个缺陷先写复现它的测试，看着它失败，再修复。
5. **零警告。**编译、测试与运行时输出的警告当场处理，不留到下一轮。
6. **遗留要写下来。**没做完、没验证、有风险的事项写进 [log.md](log.md) 的“遗留”，下一轮先看它。
7. **范围不悄悄扩大。**新想法记入 plan.md 的待定区，不在当轮顺手实现。

## 每轮的固定检查

- `./mvnw -f desktop/pom.xml -B -ntp clean verify`（格式、编译、单元、接口、存储与界面测试）
- 启动应用，控制台 0 条警告，记录冷启动时间
- 对照本轮的验收条件，逐条记录证据
