# 界面设计

## 概念：蓝晒，图形先于文字

“工坊”里最接近数据工程的手艺是蓝晒（cyanotype）：普鲁士蓝的底、白色的线，工程图纸就是这样印出来的。
数艺工坊借它的颜色与秩序感：侧栏是一块极淡渐变的普鲁士蓝“底片”，内容区是冷白的“图纸”，
状态色全部取冷调，只有失败与警告带一点温度，好让它们被一眼看见。

图纸用线条与图形说话，而不是用段落。所以界面的第一原则是**图形先于文字**：

- 每个状态是一个形状加一种颜色：后台是一个环，运行是一根柱，任务是一张卡，结果是一个勾或叉。
- 文字只留名字与数字；一句话的解释放进悬停提示（“ⓘ”或图形本身的提示），不印在界面上。
- 能点的就是图形本身：流水线的一条泳道、一根运行柱、图里的一张任务卡、时间线上的一个点。
- 动只为回应变化：环在状态变化时画一圈，柱子长到新的高度，结果的勾自己画出来，运行中的任务的连线在流动。

第一版（2026-10-27）只在运行纹带一处用力，其余都是文字与表格；第二版（2026-10-28）按“清新易懂、
以视觉与动态图形为主”的要求，把表格与说明句换成了下面的图形。

引擎内置 板岩 `#4F7290`（深色主题依次 `#5DB2E6`、`#A996E8`、`#8EA9C2`），底色是同色的淡化。

深色主题：背景 `#0E1822` → `#0B141C`，面板 `#15232F`，正文 `#DCE6EE`，次要 `#8EA2B4`，细线 `#24384A`，
侧栏 `#0A1F30` → `#08303A`，强调 `#5DB2E6`。“跟随系统”时读取 Windows 的应用主题设置。
所有文字与背景的对比度不低于 4.5:1，状态色另配形状（环、勾、叉）或提示，不只靠颜色区分。写成文字时用压暗
的一档（浅色：成功 `#1F7A6F`、失败 `#A33E56`、警告 `#8C6A1E`），输入框的提示文字是 `#71859A`
（深色 `#7F94A6`）。实现时按 WCAG 公式逐对核算过：最初的雾灰 `#61748A` 在冰川纸上只有 4.26:1、白字配
`#2F86C1` 只有 3.96:1，所以改成了上面的值。

## 字体

- **中文与界面文字：**系统字体。Windows 用“Microsoft YaHei UI”，macOS 用“PingFang SC”，
  Linux 用“Noto Sans CJK SC”；启动时按列表取第一个已安装的。
- **数字与英文标识：**内置 Barlow 1.408（SIL OFL，Medium 与 SemiBold 两个字重），用于单独显示的数字
  （延迟、成功率、耗时、指标）、作业与 DAG 的名字和应用的英文名。它的字形出自公路标识，紧凑、工程感强，
  和蓝晒图纸气质一致。只用在纯拉丁字符的标签上，中文从不落到这个字体。
- **日志与长值：**系统等宽字体（Consolas / Menlo / DejaVu Sans Mono），只在日志与校验和这类长值上出现。

字号阶梯（px）：12 说明与小标签、13 正文、15 区块标题与环中的数字、18 中号数字、20 视图标题、
22–24 指标与延迟、28 大号数字。字重 400 / 500 / 600，不用斜体，标题不靠颜色强调某一个词。

## 间距、圆角与层次

- 间距按 4 的倍数：4、8、12、16、24、32；内容区内边距 24，区块之间 20–28。
- 圆角有层级：总览的三块信息块 12，任务卡、指标块、泳道与侧滑面板 10，输入框与按钮 6，运行按钮（胶囊形）、
  标签片与圆环整圆。
- 层次靠留白、细线与淡色底：只有浮层（菜单、提示、通知、侧滑面板）和悬停中的可点任务卡有一层冷色阴影
  （`#0E2A40`，不透明度 18%）。选中的泳道用淡青底，选中的运行柱用一圈深色描边。

## 布局

```
┌──────────────┬──────────────────────────────────────────────────────────┐
│  数艺工坊      │ 总览                              ○ 引擎 4 ms  ○ Airflow 3 ms ⟳ │ 顶栏 56
│  DataCraft    │──────────────────────────────────────────────────────────│
│  ◎ 总览        │                                                          │
│  ▷ 作业        │   内容区：左对齐，内边距 24                                 │
│  ⇉ 流水线      │                                                          │
│  ∿ 活动        │                                                          │
│  ⚙ 设置        │                                                          │
│  [本机部署 ▾]  │                                                          │
└──────────────┴──────────────────────────────────────────────────────────┘
  侧栏 208（可收起到 64，只留图标）
```

- 侧栏：应用名、四个主视图、底部是设置与当前连接的切换。选中项是一条 3 px 的青线与提亮的文字。
- 顶栏：左侧是视图标题，右侧是两个后台的小环与延迟；悬停看详情。
- 区块标题前有一个青色图标，告诉人这一块是什么，而不是用一句说明。
- 首次窗口以 1280 × 800 为上限，使用屏幕可用区域约 90%，居中显示；这是包含标题栏的逻辑尺寸。
  常规最小尺寸为 960 × 640，工作区更小时以实际可用区域为限；不再次乘 DPI，避免高缩放时越界。
  [JavaFX 的可用区域](https://openjfx.io/javadoc/25/javafx.graphics/javafx/stage/Screen.html#getVisualBounds())
  已考虑任务栏、菜单栏与缩放。1366 × 728 的工作区首次为 1229 × 655，1920 × 1040 则为 1280 × 800。
- 恢复窗口时选择与旧位置重叠最多的显示器，将四边放回其可用区域；显示器断开或保存值损坏时居中重设。
  最大化单独保存状态，保留最大化前的普通窗口位置与尺寸。
- 窗口进入小于 1100 的宽度时自动收起侧栏，为正文与按钮留出空间；仍可手动展开，回到宽窗恢复用户偏好。
- 流水线泳道的名称列可从 220 缩到 120 px，长名称省略并可悬停查看全名，
  为调度开关和触发按钮保留空间，页面不因固定名称宽度出现横向滚动。

### 总览

```
┌─────────────────┐ ┌─────────────────┐ ┌──────────────────────────┐
│ (◎) 引擎 API     │ │ (✲) Airflow      │ │ (◔) 近期成功率             │
│     4 ms         │ │     3 ms         │ │ 82%   ○14 ○3 ○1           │
│     作业 7 个     │ │     调度器心跳 刚刚 │ │                          │
└─────────────────┘ └─────────────────┘ └──────────────────────────┘
⇉ 流水线
 ⏱ datacraft_engine_jobs   ▮▮▮▮▮▮▮▮▮▮  ○ 40 分钟前                     ▷
 ↖ datacraft_sftp_ingest   ··········  ○ 尚未运行            ⏸ 已暂停   ▷
∿ 最近运行
 ⇉ ●─●──────●─────────●────────●─────────●───────●●
 ▷ ─────────────────────────────────────────────────
   10-27 00:10                                    现在
 ⇉ datacraft_spark_etl   ○ 01:10:00                 （最新的四次）
```

- 两个后台各是一个环：绿色满环是正常，四分之一环是连接中，红色是不可达或令牌错误；环里是后台的图标。
- 第三块是甜甜圈：最近运行里成功、失败、运行中、等待各占多少，中间是成功率；为零的项不进图例。
- 每条流水线一行：调度方式的图标（时钟或手动）、名字、最近 10 次运行的柱（颜色是结果，高度是耗时）、
  上次的状态与时间、暂停标记、一个触发按钮。点这一行进入流水线视图，点 ▷ 直接打开它的触发面板。
- 最近运行画在时间线上：上一道是流水线，下一道是作业，从最早一次到“现在”，一个点一次运行；悬停看名字、
  状态、时间与耗时，点它打开对应的流水线或作业。线下只按名字列出最新的四次。

### 作业

左侧是作业列表：运行位置的图标（JVM、Spark、内置）与名字，悬停看一句说明。右侧依次是：

- 头部：一个圆底图标与作业名，下面一行说明；
- 参数：每行一个键、一个“ⓘ”与一个输入框，框里只写“必填”“可不填”或默认值，解释在 ⓘ 里；
- 运行按钮（胶囊形）：运行中变成转动的圆与“停止等待”，旁边是已用的秒数；“预设”是一个菜单；
- 结果：一个自己画出来的勾或叉、耗时，一行消息（过长时省略，悬停看全文），指标是一排数字块
  （行数、列数、字节），校验和这类长值单独一行、可一键复制；
- 最近运行：这个作业最近 20 次运行的柱。

### 流水线

```
 ⏱ datacraft_engine_jobs   ▮▮▮▮▮▮▮▮▮▮▮▮  ○ 40 分钟前        [●━] ▷   ← 选中的泳道是淡青底
 ↖ datacraft_spark_etl     ▮▮▮▮▮▮        ○ 3 分钟前         [●━] ▷
────────────────────────────────────────────────────────────────
⇉ datacraft_engine_jobs                                   [▷ 触发运行]
∿ 运行   ▁▁▁▁▁▁▁▁▁▁▁▁▁█████████▇██▌   ← 点一根柱选择那次运行
         ○ 成功  ⏱ 定时  ◷ 00:33:00  ⏲ 48 s
⇉ 任务 ⓘ
 ┌──────────┐     ┌──────────┐     ┌──────────────┐
 │○ noop     │────▶│○ echo     │────▶│○ spark_version│   ← 点一张卡看它的日志
 │  18 s     │     │  18 s     │     │  18 s         │
 └──────────┘     └──────────┘     └──────────────┘
```

- 上方每条流水线一条泳道，带调度开关与触发按钮；点泳道选中它。
- 选中的流水线：最近 25 次运行画成柱，点一根柱就选中那次运行，它下面是几个标签片（状态、触发方式、开始、耗时），
  运行 ID 在悬停提示里。
- 任务画成这条流水线本来的样子：按 Airflow 给出的上下游关系从左到右排列，卡片的边框与小环是这次运行里
  该任务的状态，下方是耗时；运行中的任务，指向它的连线在流动。点卡片在侧滑面板里看它的日志。
  形状读不到时，任务按开始时间排成一行。
- “触发运行”打开侧滑面板：已知 DAG 的参数用表单（同作业），其他 DAG 用 JSON。

### 活动

每条一行：来源的图标（引擎、Airflow、应用），颜色是这件事的结果；一句话；右侧是时间。按来源筛选的分段按钮
也是图标加名字。没有记录时是一个淡色图标与“还没有活动”。

### 设置

- 连接：名称、地址、令牌、用户名与口令；“加密保存”是一个开关，加密方式在 ⓘ 里。“测试连接”的结果是
  两个带图标的小环与延迟。
- 外观：三块小窗口预览（浅色、深色、半明半暗的“跟随系统”），点哪块就是哪个主题；“减少动效”是开关。
- 刷新：“标准”（闪电图标）与“节能”（叶子图标）的分段按钮与作业等待上限，各自的解释在 ⓘ 里。
- 本机数据：位置（旁边是打开文件夹的图标按钮）、占用的大小与“清除”。

## 组件

| 组件 | 是什么 | 交互与动效 |
| --- | --- | --- |
| `StatusRing` | 一个环：底圈加一段状态色的弧，中间可放图标 | 状态变化时弧从顶部画到新长度（420 ms）；悬停说明状态 |
| `Donut` | 按状态切分的环，中间是成功率 | 第一次有数据时画入（520 ms） |
| `RunBars` | 最近若干次运行的柱：颜色是结果，高度是耗时（相对最长一次取平方根，短的也看得见），运行中为满高 | 高度变化时长到新高度（240 ms）；悬停看状态、时间、耗时与运行 ID；可选时点一根柱选中 |
| `TimeStrip` | 两道时间线上的点 | 悬停看详情，点开对应的流水线或作业 |
| `TaskGraph` | DAG 的任务卡与曲线连线（布局见 `GraphLayout`：列是从起点开始的最长路径，行保持原顺序） | 卡片状态变化时轻轻放大一次；运行中任务的入边流动；点卡片看日志 |
| `RunMark` | 圆里的勾或叉 | 新结果到达时圆落定、勾或叉自己画出（320 ms） |
| `BusyRing` | 四分之三的环 | 只在等待运行结果时转动，视图隐藏时停下 |
| 标签片 `chip` | 小图标加一两个词 | 静态 |
| `ⓘ` | 一个可悬停的小图标 | 悬停显示原本写在界面上的那句说明 |
| `EmptyState` | 淡色圆底里的大图标、一句短话、一个按钮 | 静态 |
| 主题预览 | 一个画着侧栏与内容区配色的小窗口 | 选中时青色描边 |
| 通知 | 右下角：勾、叉或 i 的图标加一句话 | 出现 160 ms 上浮淡入，4 s 后淡出，失败保留到关闭 |

## 动效

只为用户的操作或状态变化而动，并且都很短：视图切换淡入 120 ms；侧滑面板 160 ms 缓出；通知 160 ms；
环 420 ms、甜甜圈 520 ms、柱 240 ms、勾与叉 320 ms、任务卡 140 ms × 2。循环的只有两处，且都有边界：
等待运行结果时的转圈（视图隐藏即停），运行中任务的连线流动（流水线视图隐藏即停）。“减少动效”打开时
以上全部改为直接切换，转圈与流动也停下。

## 文案

- 用使用者的词：作业、流水线、运行、任务、连接；不用“端点”“负载”“实体”。
- 界面上的字只留名字、数字与一两个词的标签；空状态一句短话（“先连接你的引擎与 Airflow”）；解释放进提示。
- 按钮说清楚会发生什么：“运行作业”“停止等待”“触发运行”“测试连接”“保存”。同一个动作在按钮、
  提示与活动记录里用同一个词。
- 错误说明发生了什么与怎么办，不道歉，不含糊；错误是界面上唯一可以是完整句子的地方。

## 设计复核

对照常见的模板化做法，以下是有意的取舍与原因：

- **卡片：**只在三处用：总览顶部三块信息（三件不同的事，不是一墙同样的卡）、DAG 图里的任务卡（它们就是
  图的节点）、作业结果的指标块（数字本身就是要看的东西）。其余是平面泳道与细线。
- **大数字：**只给真正要看的数字：延迟、成功率、指标；不为装饰而放大。
- **全大写的眉标、居中点连接的元信息串、给每个标题加标签**：都不用；区块标题前是一个有含义的图标。
- **只在一个词上变色或加粗的标题**：标题保持单一字重与颜色。
- **近黑底配单一荧光色的深色主题**：深色主题用带蓝调的夜色，强调色是降低饱和度的天青。
- **装饰性渐变与动效**：渐变只在侧栏、应用背景与三块信息块，幅度很小；动效都回应一次变化，没有为动而动的
  循环。
