# 界面设计

## 概念：蓝晒

“工坊”里最接近数据工程的手艺是蓝晒（cyanotype）：普鲁士蓝的底、白色的线，工程图纸就是这样印出来的。
数艺工坊借它的颜色与秩序感：侧栏是一块极淡渐变的普鲁士蓝“底片”，内容区是冷白的“图纸”，
状态色全部取冷调，只有失败与警告带一点温度，好让它们被一眼看见。

整套界面只在一处用力：**运行纹带**。每个作业与 DAG 旁边是一条由最近若干次运行组成的细带，
每段一种状态色，像晒图时一格一格曝出的刻度。它是总览与流水线列表的主角，其余元素保持安静：
没有卡片墙，没有每块区域都带的阴影，没有装饰性的渐变块。

## 色彩

浅色主题（默认）：

| 名称 | 值 | 用途 |
| --- | --- | --- |
| 普鲁士墨 | `#12304A` | 侧栏渐变起点、深色文字背景 |
| 深潟 | `#0E4D5E` | 侧栏渐变终点 |
| 冰川纸 | `#EDF2F6` → `#E6EDF3` | 应用背景（自上而下极淡的渐变） |
| 霜面 | `#F8FAFC` | 面板、表格、输入框 |
| 板岩墨 | `#1C2C3B` | 正文 |
| 雾灰 | `#566A80` | 次要文字、表头 |
| 细线 | `#D3DDE6` | 分隔线、边框 |
| 青线 | `#2F86C1` | 强调：选中、运行中、焦点；主按钮的填充是它压暗的 `#2A78AE` → `#246A9B`，白字 |

状态色（两个主题共用色相，深色主题提高明度）：

| 状态 | 浅色 | 深色 | 对应 |
| --- | --- | --- | --- |
| 成功 | `#2A9D8F` 铜绿 | `#4CC2B2` | 作业 SUCCEEDED、DAG/任务 success |
| 运行中 | `#2F86C1` 青线 | `#5DB2E6` | running、deferred、restarting |
| 等待 | `#8FA3B8` 薄雾 | `#7F93A8` | queued、scheduled、up_for_retry、up_for_reschedule |
| 失败 | `#C8506A` 冷玫瑰 | `#E67A90` | FAILED、failed、upstream_failed |
| 警告 | `#C99A3C` 赭 | `#E0B860` | 数据过期、退避中、令牌即将过期 |
| 无 | `#C3CFDA` | `#3A4B5A` | skipped、removed、尚无运行 |

深色主题：背景 `#0E1822` → `#0B141C`，面板 `#15232F`，正文 `#DCE6EE`，次要 `#8EA2B4`，细线 `#24384A`，
侧栏 `#0A1F30` → `#08303A`，强调 `#5DB2E6`。“跟随系统”时读取 Windows 的应用主题设置。
所有文字与背景的对比度不低于 4.5:1，状态色另配文字或图形，不只靠颜色区分。状态色本身用于圆点与纹带；
写成文字时用压暗的一档（浅色：成功 `#1F7A6F`、失败 `#A33E56`、警告 `#8C6A1E`），输入框的提示文字是
`#71859A`（深色 `#7F94A6`）。实现时按 WCAG 公式逐对核算过：最初的雾灰 `#61748A` 在冰川纸上只有 4.26:1、
白字配 `#2F86C1` 只有 3.96:1，所以改成了上面的值。

## 字体

- **中文与界面文字：**系统字体。Windows 用“Microsoft YaHei UI”，macOS 用“PingFang SC”，
  Linux 用“Noto Sans CJK SC”；启动时按列表取第一个已安装的。
- **数字与英文标识：**内置 Barlow 1.408（SIL OFL，Medium 与 SemiBold 两个字重），用于单独显示的大号指标、
  顶栏的延迟与应用的英文名。它的字形出自公路标识，紧凑、工程感强，和蓝晒图纸气质一致。只用在纯拉丁
  字符的标签上，中文从不落到这个字体。Barlow 的数字是比例宽度（实测“1”宽 35、“0”宽 57），而 JavaFX
  无法打开等宽数字特性，所以表格里的数字仍用系统中文字体（其数字等宽，列能对齐）；顶栏的延迟标签设最小
  宽度，数字变化时不跳动。
- **日志：**系统等宽字体（Consolas / Menlo / DejaVu Sans Mono），只在日志查看器里出现。

字号阶梯（px）：12 说明、13 正文与表格、15 区块标题、20 视图标题、28 大号指标。字重 400 / 500 / 600，
不用斜体，不全部加粗，标题不靠颜色强调某一个词。

## 间距、圆角与层次

- 间距按 4 的倍数：4、8、12、16、24、32；内容区内边距 24，区块之间 24，表格行高 36。
- 圆角有层级：主面板 10，输入框与按钮 6，状态胶囊整圆；表格与列表本身不加圆角。
- 层次靠留白与细线，而不是阴影：只有浮层（菜单、提示、通知、对话框）有一层冷色阴影
  （`#0E2A40`，不透明度 18%，半径 18，下移 6）。选中的详情区用霜面加 1 px 青线左边框表示焦点。

## 布局

```
┌──────────────┬──────────────────────────────────────────────────────────┐
│  数艺工坊      │ 总览                            ● 引擎 23 ms   ● Airflow 正常 │ 顶栏 56
│  DataCraft    │──────────────────────────────────────────────────────────│
│               │                                                          │
│  ◎ 总览        │   内容区：左对齐，最大宽度不限，内边距 24                   │
│  ▤ 作业        │                                                          │
│  ⇉ 流水线      │                                                          │
│  ≡ 活动        │                                                          │
│               │                                                          │
│  ⚙ 设置        │                                                          │
│  [本机部署 ▾]  │                                                          │
└──────────────┴──────────────────────────────────────────────────────────┘
  侧栏 208（可收起到 64）
```

- 侧栏：应用名、四个主视图、底部是设置与当前连接配置的切换。选中项是一条 3 px 的青线与提亮的文字，
  不用整块高亮。
- 顶栏：左侧是视图标题，右侧是两个后台的状态点与延迟；状态变化时点的颜色渐变 200 ms。
- 内容区一律左对齐；表格的数字列右对齐。

### 总览

```

────────────────────────────────────────────────────────────────────────────
流水线
datacraft_engine_jobs     每天 02:00     ▮▮▮▮▮▮▮▯▮▮   上次 成功  2 分钟前
datacraft_spark_etl       手动           ▮▮▮▮▮▯▯▯▯▯   上次 失败  1 小时前
datacraft_sftp_ingest     手动           ▯▯▯▯▯▯▯▯▯▯   尚未运行

最近运行                                   时间       状态     耗时

```

### 作业

左侧是作业列表（名称与一行描述），右侧是所选作业：参数编辑器（已知参数给出提示与校验，可加自定义键值）、
预设（保存与套用）、“运行”按钮、结果（状态、消息、指标表）与这个作业的运行纹带和最近运行。
运行中按钮变为“停止等待”，并显示已用时间；作业在后台继续运行，界面只是不再等待结果。

### 流水线

上半部分是 DAG 表（名称、调度、运行纹带、暂停开关），选中后下半部分依次是运行表（运行 ID、状态、开始、
耗时、触发方式）与所选运行的任务实例（状态、尝试次数、耗时）。“触发运行”打开一个侧滑面板：
已知 DAG 的参数用表单，其他 DAG 用 JSON 编辑。任务行的“日志”在同一侧滑面板里分段加载，最多保留 2 MB。

### 活动

按时间倒序的事件流：连接状态变化、运行开始与结束、触发、暂停与恢复、错误。每条一行：时间、来源、
一句话描述，失败与警告带状态色。可按来源筛选，可清除。

### 设置

连接配置（名称、引擎地址与令牌、Airflow 地址、用户名与口令、“保存秘密”开关、“测试连接”）、
外观（浅色、深色、跟随系统；减少动效）、刷新（标准、节能）、本机数据（位置、占用、清除缓存）。

## 组件

- **状态徽标：**8 px 圆点加文字（“正常”“不可达”“令牌错误”），不用色块胶囊包裹文字。
- **运行纹带：**最近 10 次（总览）或 20 次（流水线）运行，每段 6×14，间隔 2，最近的在右；
  悬停显示运行 ID、状态、开始时间与耗时；空位用“无”色。
- **参数编辑器：**每行一个键值，已知键显示说明与默认值，必填键缺失时“运行”不可用并说明缺什么。
- **空状态：**一句话说明原因，一个能解决它的按钮，例如“还没有连接配置” + “添加连接”。
- **通知：**右下角，最多同时 3 条，4 s 后淡出，失败通知保留到用户关闭。

## 动效

只为用户的操作或状态变化而动，并且都很短：视图切换淡入 120 ms；侧滑面板 160 ms 缓出；
通知出现 160 ms；状态点颜色过渡 200 ms。不做循环动画，“运行中”用一条细的不确定进度线表示。
“减少动效”打开时以上全部改为直接切换。

## 文案

- 用使用者的词：作业、流水线、运行、任务、连接；不用“端点”“负载”“实体”。
- 按钮说清楚会发生什么：“运行作业”“触发运行”“暂停调度”“测试连接”“保存”。同一个动作在按钮、
  提示与活动记录里用同一个词。
- 错误说明发生了什么与怎么办，不道歉，不含糊：
  “无法连接引擎 API（127.0.0.1:8088）：连接被拒绝。确认服务已启动，或在设置里检查地址。”
- 句子式，不加感叹号，界面上不出现内部异常类名；技术细节放在活动记录的展开项里。

## 设计复核

对照常见的模板化做法，以下是有意避开的地方与原因：

- **卡片墙**（每块内容一张同样圆角、同样阴影的卡片）：改为细线分隔的平面区块，只有浮层有阴影，
  层次由留白承担。
- **大数字配小标签的指标块**：总览的主角换成运行纹带，指标以一行文字的形式跟在状态后面。
- **全大写的眉标、居中点连接的元信息串、给每个标题加标签**：都不用；中文界面本身也不需要。
- **只在一个词上变色或加粗的标题**：标题保持单一字重与颜色。
- **近黑底配单一荧光色的深色主题**：深色主题用带蓝调的夜色，强调色是降低饱和度的天青。
- **装饰性渐变**：渐变只出现在侧栏与应用背景两处，幅度很小，作用是让冷色调有纵深，而不是吸引注意。
