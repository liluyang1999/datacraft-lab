# 数艺工坊 · 界面规格

本文是界面的文字规格：概念、色彩与字体的用法、布局、每个视图、组件、动效与文案。颜色、字号、圆角、
间距与时长的数值只在 [tokens.json](tokens.json) 中定义，本文不重复；可浏览的样子见 [index.html](index.html)，
二者与本文的分工见 [界面设计基线](README.md)。

## 概念：蓝晒，图形先于文字

“工坊”里最接近数据工程的手艺是蓝晒（cyanotype）：普鲁士蓝的底、白色的线，工程图纸就是这样印出来的。
数艺工坊借它的颜色与秩序感：侧栏是一块极淡渐变的普鲁士蓝“底片”，内容区是冷白的“图纸”，
状态色全部取冷调，只有失败与警告带一点温度，好让它们被一眼看见。

图纸用线条与图形说话，而不是用段落。所以界面的第一原则是**图形先于文字**：

- 每个状态是一个形状加一种颜色：后台是一个环，运行是一根柱，任务是一张卡，结果是一个勾或叉。
- 文字保留名字、数字与紧凑摘要；短解释放进悬停提示，长诊断与原始结果放进可用键盘打开的详情。
  详情可滚动、选取和复制全文，读屏读取实际内容；摘要省略或数字缩写不改变详情和复制的原值。
- 能点的就是图形本身：流水线的一条泳道、一根运行柱、图里的一张任务卡、时间线上的一个点。
- 动只为回应变化：环在状态变化时画一圈，柱子长到新的高度，结果的勾自己画出来，运行中的任务的连线在流动。

第一版（2026-10-27）只在运行纹带一处用力，其余都是文字与表格；第二版（2026-10-28）按“清新易懂、
以视觉与动态图形为主”的要求，把表格与说明句换成了下面的图形。第三版（2026-11-20，1.0.0）把全部数值
收进一份令牌，由它生成两个主题；侧栏换成标志加名称与版本、药丸形导航；总览三块等宽排列；新增实时的
“监控”视图与侧栏提醒计数、设置里的“关于”；字号、圆角与间距全部落在刻度上，由 `build.py --check` 把关。

## 色彩

两个主题共用一套令牌名，值只写在 [tokens.json](tokens.json)：`build.py` 把它生成为桌面的 `light.css`、
`dark.css`（JavaFX 的 `-dc-*` 查找色）与原型的 `tokens.css`（`--dc-*`）。下表说明各组令牌的用途。

| 令牌组 | 令牌 | 用途 |
| --- | --- | --- |
| 图纸 | `bg-top` → `bg-bottom`、`surface`、`surface-hover`、`surface-selected`、`input`、`prompt` | 内容区自上而下极淡的冷白渐变；面板、输入框、任务卡与指标块；悬停与选中；输入框提示 |
| 文字与线 | `text`、`text-secondary`、`line`、`line-strong` | 正文、次要文字、分隔线与边框 |
| 青线 | `accent`、`accent-text`、`accent-fill-top` → `accent-fill-bottom`、`accent-wash`、`on-accent`、`focus` | 选中、运行中、焦点、标题图标；主按钮的压暗填充与白字；折线下的淡填充 |
| 底片（侧栏） | `side-top` → `side-bottom`、`side-text`、`side-text-active`、`side-hover`、`side-active`、`side-mark`、`side-line` | 普鲁士蓝渐变的侧栏；导航文字；悬停与选中的药丸；选中项左缘的青色标记 |
| 状态 | `success`、`running`、`waiting`、`deferred`、`failed`、`warning`、`none` 及其 `-text`、`-wash` | 环、柱、点、格与卡片边框；写成文字时用压暗的 `-text` 一档；提醒行与结果块的淡底 |
| 提醒 | `badge`、`on-badge` | 侧栏与区块标题旁的提醒计数 |
| 数据图形 | `ring-track`、`chip`、`tile-tint`、`kind-*` 与 `kind-*-wash` | 环的底圈与容量格的空格、标签片、信息块的渐变、作业运行位置（JVM / Spark / 内置）的颜色与圆底 |
| 层次 | `shadow`、`scrim` | 只给浮层（菜单、提示、通知、侧滑面板）与它的遮罩 |

状态与类型的映射：成功 = 作业 SUCCEEDED、DAG/任务 success；运行中 = running、restarting；`deferred`
另有雾紫，只用于资源池里延后任务占的槽；等待 = queued、scheduled、up_for_retry、up_for_reschedule；
失败 = FAILED、failed、upstream_failed；警告 = 数据过期、退避中、状态异常、资源池已满；无 = skipped、removed、尚无运行。
作业的运行位置各有一色，只用于它的图形，不表示状态。

“跟随系统”时读取 Windows 的应用主题设置。文字与背景至少 4.5:1；状态色另配形状（环、勾、叉、
半环）或提示，不只靠颜色区分。`ThemeContrastTest` 读取真实 CSS 检查每个主题的 15 对文字与背景，
`tests/design` 另查提醒计数与三种状态文字在各自淡底上的对比度。配色测试不替代键盘操作、控件语义和
原生无障碍验证。

## 字体

- **中文与界面文字：**系统字体。Windows 用“Microsoft YaHei UI”，macOS 用“PingFang SC”，
  Linux 用“Noto Sans CJK SC”；启动时按列表取第一个已安装的。
- **数字与英文标识：**内置 Barlow 1.408（SIL OFL，Medium 与 SemiBold 两个字重），用于单独显示的数字
  （延迟、成功率、耗时、指标）、作业与 DAG 的名字和应用的英文名。它的字形出自公路标识，紧凑、工程感强，
  和蓝晒图纸气质一致。只用在纯拉丁字符的标签上，中文从不落到这个字体。
- **日志与长值：**系统等宽字体（Consolas / Menlo / DejaVu Sans Mono），只在日志与校验和这类长值上出现。

字号阶梯（px，令牌 `type`）：12 说明与小标签（caption）、13 正文（body）、15 区块标题与按钮、空状态
（section）、18 中号数字与侧栏名称（lead）、20 视图标题（title）、24 指标与延迟（metric）、28 大号数字
（display）。阶梯外的字号不许出现。字重 400 / 500 / 600，不用斜体，标题不靠颜色强调某一个词。

## 间距、圆角与层次

- 间距按 4 的节奏（令牌 `space`）：4、8、12、16、20、24、28、32、48；2 与 6 只用于紧凑控件内部，
  1 px 只用于分隔线。内容区内边距 24，区块之间 28。
- 圆角有层级（令牌 `radius`）：信息块 12，任务卡、指标块、泳道、提醒行、延迟行与侧滑面板 10，
  导航药丸、监控里的行与通知 8，输入框与按钮 6，容量格与状态标记 4，运行按钮（胶囊形）、标签片、
  提醒计数与圆环整圆。
- 层次靠留白、细线与淡色底：只有浮层（菜单、提示、通知、侧滑面板）和悬停中的可点任务卡有一层冷色阴影
  （令牌 `shadow`）。选中的泳道用淡青底，选中的运行柱用一圈深色描边。

│ ◎ 总览        │                                                          │
│ ▷ 作业        │   内容区：左对齐，内边距 24                                 │
│ ⇉ 流水线      │                                                          │
│▌◠ 监控     3  │   ← 选中项是左缘青色标记加淡底药丸；3 是提醒计数              │
│ ∿ 活动        │                                                          │
│ ⚙ 设置        │                                                          │
│ [本机部署 ▾]  │                                                          │
└──────────────┴──────────────────────────────────────────────────────────┘
  侧栏 208（可收起到 64，只留图标与标志）
```

- 侧栏：标志（应用图标的运行纹带：五段，第三段是运行中的青色）加“数艺工坊”与版本号，五个主视图，
  底部是设置与当前连接的切换。导航项是贴住侧栏左缘、右侧圆角 8 的药丸：选中时左缘 3 px 青线、
  `side-active` 淡底与提亮的文字。监控项右侧有提醒计数（`badge` 圆角药丸，超过 99 显示 99+），
  读屏读作“监控，3 项需要关注”；收起时计数移到图标右上角。
- 顶栏：左侧是视图标题，右侧是两个后台的小环与延迟；悬停看详情。
- 区块标题前有一个青色图标，告诉人这一块是什么，而不是用一句说明；需要时标题后跟一个计数。
- 快捷键：Ctrl+1 至 Ctrl+6 依侧栏顺序切换视图，Ctrl+R 刷新。
- 首次窗口以 1280 × 800 为上限，使用屏幕可用区域约 90%，居中显示；这是包含标题栏的逻辑尺寸。
  常规最小尺寸为 960 × 640，工作区更小时以实际可用区域为限；不再次乘 DPI，避免高缩放时越界。
  [JavaFX 的可用区域](https://openjfx.io/javadoc/25/javafx.graphics/javafx/stage/Screen.html#getVisualBounds())
  已考虑任务栏、菜单栏与缩放。1366 × 728 的工作区首次为 1229 × 655，1920 × 1040 则为 1280 × 800。
- 恢复窗口时选择与旧位置重叠最多的显示器，将四边放回其可用区域；显示器断开或保存值损坏时居中重设。
  最大化单独保存状态，保留最大化前的普通窗口位置与尺寸。
- 窗口进入小于 1100 的宽度时自动收起侧栏，为正文与按钮留出空间；仍可手动展开，回到宽窗恢复用户偏好。
- 流水线泳道的名称列可从 220 缩到 120 px，长名称省略并可悬停查看全名，
  为调度开关和触发按钮保留空间，页面不因固定名称宽度出现横向滚动。
- 同一数据目录只运行一个数艺工坊：再次启动时把已打开的窗口还原并提到最前，自己退出。

│     4 ms         │ │     3 ms         │ │ 82%   ○14 ○3 ○1           │
│     作业 8 个     │ │     调度器心跳 刚刚 │ │                          │
└─────────────────┘ └─────────────────┘ └──────────────────────────┘
⇉ 流水线
 ⏱ datacraft_engine_jobs   ▮▮▮▮▮▮▮▮▮▮  ○ 40 分钟前                     ▷
 ↖ datacraft_sftp_ingest   ··········  ○ 尚未运行            ⏸ 已暂停   ▷
∿ 最近运行
 ⇉ ●─●──────●─────────●────────●─────────●───────●●
 ▷ ─────────────────────────────────────────────────
   10-27 00:10                                    现在
 ⇉ datacraft_spark_etl   ○ 01:10:00                 （最新的四次）
```

- 三块信息块等宽排成一行，与下面的泳道同宽对齐。两个后台各是一个环：绿色满环是正常，四分之一环是
  连接中，红色是不可达或令牌错误；环里是后台的图标。块的右上角是一个安静的 ⓘ，点开是连接详情全文。
- 第三块是甜甜圈：最近运行里成功、失败、运行中、等待各占多少，中间是成功率；为零的项不进图例。
- 每条流水线一行：调度方式的图标（时钟或手动）、名字、最近 10 次运行的柱（颜色是结果，高度是耗时）、
  上次的状态与时间、暂停标记、一个触发按钮。点这一行进入流水线视图，点 ▷ 直接打开它的触发面板。
- 最近运行画在时间线上：上一道是流水线，下一道是作业，从最早一次到“现在”，一个点一次运行；悬停看名字、
  状态、时间与耗时，点它打开对应的流水线或作业。线下只按名字列出最新的四次。
- 本机历史读取失败时保留已知作业记录与统计，并显示“运行记录未更新”的详情入口；成功读到空列表才清空记录。

### 作业

左侧是作业列表：运行位置的图标（JVM、Spark、内置）与名字，悬停看一句说明。上方用紧凑搜索框、
运行位置筛选与清除入口查找作业，匹配名称和中文说明；空结果明确显示没有匹配项。
搜索与分类只改变可见列表，隐藏当前项不会切换右侧作业或丢失草稿；清除后恢复当前项高亮。
从总览打开指定作业时清除筛选并显示目标。控件保留可访问名称与键盘焦点，不用占位文字承担唯一标签。
右侧依次是：

- 头部：一个圆底图标与作业名，下面一行说明；
- 参数：每行一个键、一个“ⓘ”与一个输入框，框里只写“必填”“可不填”或默认值，解释在 ⓘ 里；
- 运行按钮（胶囊形）：运行中变成转动的圆与“停止等待”，旁边是已用的秒数；“预设”是一个菜单；
- 结果：一个自己画出来的勾或叉、耗时与一行消息摘要；“结果详情”打开全文。“指标详情”保留指标原始键和值，
  数字块中的大计数可缩写，校验和这类长值单独一行、可一键复制原值；
- 最近运行：这个作业最近 20 次运行的柱。切换作业立即清除旧柱并显示读取状态；刷新失败保留已有记录并明确提示，
  不显示成空历史，用户可刷新重试。

输入表单在重复自定义键、键与已知参数冲突或有值却没有键时给出明确提示，禁止发送歧义参数。
新作业 `csv-quality` 复用相同的参数与结果区域，显示行列数、空白数和重复数，不另建重复的导航页面。

### 流水线

```
 ⏱ datacraft_engine_jobs   ▮▮▮▮▮▮▮▮▮▮▮▮  ○ 40 分钟前        [●━] ▷   ← 选中的泳道是淡青底
 ↖ datacraft_spark_etl     ▮▮▮▮▮▮        ○ 3 分钟前         [●━] ▷
────────────────────────────────────────────────────────────────
⇉ datacraft_engine_jobs                                   [▷ 触发运行]
∿ 运行   ▁▁▁▁▁▁▁▁▁▁▁▁▁█████████▇██▌   ← 点一根柱选择那次运行
         ○ 成功  ⏱ 定时  ◷ 00:33:00  ⏲ 48 s
⇉ 任务 ⓘ
 ┌──────────┐     ┌──────────┐     ┌──────────────┐
 │○ noop     │────▶│○ echo     │────▶│○ spark_version│   ← 点一张卡看它的日志
 │  18 s     │     │  18 s     │     │  18 s         │
 └──────────┘     └──────────┘     └──────────────┘
```

- 上方每条流水线一条泳道，带调度开关与触发按钮；点泳道选中它。
- 选中的流水线：最近 25 次运行画成柱，点一根柱就选中那次运行，它下面是几个标签片（状态、触发方式、开始、耗时），
  运行 ID 在悬停提示里。
- 任务画成这条流水线本来的样子：按 Airflow 给出的上下游关系从左到右排列，卡片的边框与小环是这次运行里
  该任务的状态，下方是耗时；运行中的任务，指向它的连线在流动。点卡片在侧滑面板里看它的日志。
- 日志每页 100 行，页脚显示当前行号范围与总行数；首页、前后页、末页按钮支持键盘。
  新日志只在末页自动跟随，阅读前页时不跳走；服务端的“继续读取”与本地翻页分开。
  形状读不到时，任务按开始时间排成一行。
- “触发运行”打开侧滑面板：已知 DAG 的参数用表单（同作业），其他 DAG 用 JSON。
  两种模式可切换；字符串与自定义字段完整保留，数字、布尔、空值、嵌套结构等不能原样放回表单的配置
  留在 JSON 模式并说明原因。错误 JSON、重复字段或尾随内容不能提交，切换失败保留当前草稿。
  表单中的重名键和有值无键也在切换或提交前拦截；JSON 区域与备注各有可见标签。

- 最上面是“需要关注”：失败在前（红淡底与叉），警告在后（赭淡底与三角）。规则：后台不可达或认证失败、
  后台状态异常、DAG 文件无法解析、资源池满且有任务在等、任务等待重试、引擎在最近 10 分钟拒绝了运行。
  每行一个标题与首行摘要，“详情”打开全文；能处理的给出动作（“检查连接”去设置，“打开流水线”去那条流水线）。
  没有提醒时是一行绿色淡底的“一切正常”与更新时间。提醒的数量同时显示在侧栏。
- 两块等宽信息块：引擎的同时运行数（容量格，一格一个并发位，悬停列出正在运行的作业与已用时间）、
  自启动以来开始、成功、失败、拒绝的次数与已运行时长；没有 `/status` 的旧引擎只说明“这个引擎版本不提供
  运行状态”，不算故障。Airflow 列出元数据库、调度器、触发器与 DAG 处理器的状态点与心跳。
- 延迟与可用性：两个后台最近 120 次检查（标准刷新约 10 分钟）的折线，最新一次是一个空心点；没有回答的
  检查断开折线并在基线上留一道红色短竖；右侧是最新延迟、中位与最慢，以及回答的比例（≥ 99% 绿、
  ≥ 90% 赭、更低红）。
- 运行中的任务：所有 DAG 中运行、排队、已调度、延后、等待重试或重排的任务实例，最近开始的在前，最多 50 个；
  运行中的显示已用时间，排队的显示排队了多久，重试的标出第几次；点一行打开它的流水线。
- 资源池：每个池一条容量条（运行、排队、延后各一色，满的池文字转赭），右侧是运行、排队与空闲槽位。
- DAG 导入错误：文件名与时间，“查看错误”打开完整堆栈；没有错误时是一个绿勾与“所有 DAG 文件都能解析”。
- 监控在屏幕上时每 5 s 读取一次（节能模式 15 s），离开时每 60 s 在后台读取一次以保持侧栏计数，
  窗口最小化时完全停止；每部分各自读取，一部分失败只在该部分标注原因，不清空其他部分。

### 活动

每条一行：来源的图标（引擎、Airflow、应用），颜色是这件事的结果；一句话；右侧是时间。按来源筛选的分段按钮
也是图标加名字。没有记录时是一个淡色图标与“还没有活动”。
选中后只显示紧凑摘要与“查看详情”；全文在独立的可滚动详情中读取和复制，不挤占事件列表。

### 设置

- 连接：名称、地址、令牌、用户名与口令；“加密保存”是一个开关，加密方式在 ⓘ 里。“测试连接”的结果是
  两个带图标的小环与延迟。地址、令牌、用户名或口令编辑后立即清除旧结果；只有当前草稿最近一次测试
  能显示结果，改回原值也需要重新测试。修改名称或“加密保存”不影响连接结果。
- 外观：三块小窗口预览（浅色、深色、半明半暗的“跟随系统”），点哪块就是哪个主题；“减少动效”是开关。
- 刷新：“标准”（闪电图标）与“节能”（叶子图标）的分段按钮与作业等待上限，各自的解释在 ⓘ 里。
- 本机数据：位置（旁边是打开文件夹的图标按钮）、占用的大小与“清除”。清除成功后活动、作业最近运行
  和总览中的本机作业统计同步更新；远端流水线历史及本机设置、连接和参数预设保留，之后的新活动正常显示。

- 关于：应用图标、“数艺工坊”与版本号（来自构建，与安装包一致），以及当前连接的引擎与 Airflow 报告的版本；
  尚未读到时显示“—”。

连接输入、等待上限与本机位置的可见名称关联到各自控件，读屏仍能读取普通字段的实际值；令牌与口令使用密码框。

## 组件

| 组件 | 是什么 | 交互与动效 |
| --- | --- | --- |
| `StatusRing` | 一个环：底圈加一段状态色的弧，中间可放图标 | 状态变化时弧从顶部画到新长度（420 ms）；悬停说明状态 |
| `Donut` | 按状态切分的环，中间是成功率 | 第一次有数据时画入（520 ms） |
| `RunBars` | 最近若干次运行的柱：颜色是结果，高度是耗时（相对最长一次取平方根，短的也看得见），运行中为满高 | 高度变化时长到新高度（240 ms）；悬停看状态、时间、耗时与运行 ID；可选时点一根柱选中 |
| `TimeStrip` | 两道时间线上的点 | 悬停看详情，点开对应的流水线或作业 |

| 标签片 `chip` | 小图标加一两个词 | 静态 |
| `ⓘ` | 一个可悬停的小图标 | 悬停显示原本写在界面上的那句说明 |
| `EmptyState` | 淡色圆底里的大图标、一句短话、一个按钮 | 静态 |
| 主题预览 | 一个画着侧栏与内容区配色的小窗口 | 选中时青色描边 |
| 通知 | 右下角：勾、叉或 i 的图标加一句话 | 出现 160 ms 上浮淡入，4 s 后淡出，失败保留到关闭 |
| `Sparkline` | 一条延迟折线：每次检查一个点，最新在右，高度相对最慢一次留 25% 余量；底部一条基线 | 只在样本或宽度变化时重画；没有回答的检查断开折线并留红色短竖；最新一点是空心圆 |

耗时文字对超长时间使用天数或科学计数法，不因转换成毫秒溢出。

## 动效

只为用户的操作或状态变化而动，并且都很短：视图切换淡入 120 ms；侧滑面板 160 ms 缓出；通知 160 ms；
环 420 ms、甜甜圈 520 ms、柱 240 ms、勾与叉 320 ms、任务卡 140 ms × 2。循环的只有两处，且都有边界：
等待运行结果时的转圈（视图隐藏即停），运行中任务的连线流动（流水线视图隐藏即停）。“减少动效”打开时
以上全部改为直接切换，转圈与流动也停下。

## 文案

- 用使用者的词：作业、流水线、运行、任务、连接；不用“端点”“负载”“实体”。
- 界面上的字只留名字、数字与一两个词的标签；空状态一句短话（“先连接你的引擎与 Airflow”）；解释放进提示。
- 按钮说清楚会发生什么：“运行作业”“停止等待”“触发运行”“测试连接”“保存”。同一个动作在按钮、
  提示与活动记录里用同一个词。
- 错误说明发生了什么与怎么办，不道歉，不含糊；错误是界面上唯一可以是完整句子的地方。

## 设计复核

对照常见的模板化做法，以下是有意的取舍与原因：

- **卡片：**只在三处用：总览顶部三块信息（三件不同的事，不是一墙同样的卡）、DAG 图里的任务卡（它们就是
  图的节点）、作业结果的指标块（数字本身就是要看的东西）。其余是平面泳道与细线。
- **大数字：**只给真正要看的数字：延迟、成功率、指标；不为装饰而放大。
- **全大写的眉标、居中点连接的元信息串、给每个标题加标签**：都不用；区块标题前是一个有含义的图标。
- **只在一个词上变色或加粗的标题**：标题保持单一字重与颜色。
- **近黑底配单一荧光色的深色主题**：深色主题用带蓝调的夜色，强调色是降低饱和度的天青。
- **装饰性渐变与动效**：渐变只在侧栏、应用背景与三块信息块，幅度很小；动效都回应一次变化，没有为动而动的
  循环。
